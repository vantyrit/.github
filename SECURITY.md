# Security Policy

Vantyr takes the security of its software seriously. This policy explains how to report a vulnerability and what you can expect from us.

## Supported versions

We provide security fixes for the latest release of each Vantyr project. Older releases are not patched unless a repository states otherwise in its own README.

## Reporting a vulnerability

Please do not report security issues through public GitHub issues, discussions, or pull requests.

Use one of the following private channels instead:

1. **GitHub private vulnerability reporting.** Open the affected repository, go to the **Security** tab, and choose **Report a vulnerability**.
2. **Email.** Send the details to im@sourav.com.bd with the subject line `Security: <repository name>`.

A useful report includes:

- A description of the issue and its potential impact
- The affected repository, version, or commit
- Steps to reproduce, or a proof of concept
- Any suggested fix, if you have one

## What to expect

- We will acknowledge your report within 3 business days.
- We will confirm whether we can reproduce the issue and share an expected timeline within 10 business days.
- We will keep you informed while a fix is prepared and credit you in the release notes if you would like that.

We ask that you give us a reasonable amount of time, up to 90 days, to release a fix before disclosing the issue publicly.

## Scope

This policy covers code published in repositories owned by the Vantyr organization. Vulnerabilities in third-party dependencies should be reported to the maintainers of those projects, although we appreciate a heads-up if they affect our software.

## Good-faith research

We will not pursue legal action against researchers who act in good faith, avoid privacy violations and service disruption, and give us the opportunity to fix a problem before it is made public.
