# Contributing to Vantyr

Thank you for taking the time to contribute. This guide applies to every repository in the Vantyr organization unless a repository provides its own CONTRIBUTING file.

## Ways to contribute

- Report a bug or request a feature by opening an issue
- Improve documentation
- Fix a bug or implement a feature through a pull request
- Review open pull requests and help others with questions

## Before you start

- Search existing issues and pull requests to avoid duplicating work.
- For anything larger than a small fix, open an issue first so we can agree on the approach before you invest time in code.
- Read the repository README for setup instructions and project-specific conventions.

## Development workflow

1. Fork the repository and clone your fork.
2. Create a branch from `main`. Use a short, descriptive name such as `fix/login-redirect` or `feature/export-csv`.
3. Make your change. Keep each pull request focused on a single concern.
4. Add or update tests and documentation where it makes sense.
5. Run the project's linters and tests locally and make sure they pass.
6. Push your branch and open a pull request against `main`.

## Commit messages

- Write the subject line in the imperative mood, for example "Fix null check in session handler".
- Keep the subject under 72 characters.
- Use the body to explain why the change is needed when it is not obvious.

## Pull request checklist

- [ ] The change is focused and the description explains what and why
- [ ] Tests and documentation are updated where relevant
- [ ] Linters and tests pass locally
- [ ] No secrets, credentials, or personal data are included

## Review process

A maintainer will review your pull request, usually within a few business days. We may ask for changes before merging. Once approved, a maintainer will merge it.

## Licensing of contributions

By submitting a contribution, you confirm that you have the right to submit it and that it may be distributed under the license of the repository you are contributing to.

## Security issues

Please do not report vulnerabilities in public issues. Follow the instructions in [SECURITY.md](SECURITY.md).

## Code of conduct

All participation is covered by our [Code of Conduct](CODE_OF_CONDUCT.md).
